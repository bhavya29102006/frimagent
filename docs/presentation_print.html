06 / SAFETY & FEASIBILITY

Deterministic Safety Gate & Zero-Regression Rule

Slide 7 of 8

How FirmAgent guarantees AI code changes can never corrupt or break production hardware:

🛡️ 7 Pre-Patch Safety Checks

  • • Hunk Count Limit: Maximum ≤ 3 hunks allowed per patch proposal.
  • • Line Count Limit: ≤ 25 total modified lines (prevents wild hallucinated rewrites).
  • • Exact Byte Match: Replaced text must match original source byte-for-byte.
  • • Disjoint Hunks: Zero overlapping or colliding hunk line ranges.
  • • Protected Range Locking: Headers, pin defines, and #includes are locked.
  • • Spec Block Integrity: Specification docstrings cannot be altered.
  • • Compilation Gate: Must compile cleanly with 0 compiler errors.

🧪 Isolated Sandbox & Zero-Regression Rule

  • • Dedicated Sandbox Clone: Patches are applied to an isolated copy in runs/.../project/.
  • • Idempotent Patching: Reads from pristine .orig backup; repeated testing never corrupts braces.
  • • Zero-Regression Rule: If even 1 previously passing test fails, the patch is instantly auto-rejected.
  • • Zero-Fix Rejection: If 0 failed tests are resolved, fix is rejected.
  • • 1-Click Safe Rollback: Instant atomic rollback from backup.
Result: 100% of applied patches pass with zero regressions
